# Data Dictionary

Generated by `generate_synthetic_company.py` (seed 42). Full tables land in
`data/generated/` (gitignored, regenerable); small previews are in
`data/sample/`. All figures are synthetic — see `docs/case_reference.md`.
Pipeline outputs (results of every module) are in `data/results/`.

## regions.csv (6 rows)

| Column | Type | Description |
|---|---|---|
| `region_id` | string | Primary key, `R01`–`R06` |
| `region_name` | string | e.g. "Haryana Belt" |
| `state` | string | Indian state |
| `complexity_index` | int 1–5 | How technically demanding the region's industrial accounts are. Haryana Belt = 5, the site of the case's 2009 coverage failure |

## accounts.csv (650 rows) — the current book of business

| Column | Type | Description |
|---|---|---|
| `account_id` | string | Primary key, `A0001`… |
| `account_name` | string | Synthetic (Faker) |
| `region_id` | string | FK → regions |
| `product_line` | string | Conveyor Systems, Elevator Systems, Bulk Material Handling, or Dumb Waiter (New Product) |
| `buyer_segment` | string | Industrial accounts: cement/steel/mining, ports/logistics, food/process plant. Dumb Waiter: builder/real estate, hotel/restaurant, hospital |
| `annual_revenue_inr` | float | Yearly revenue. Sums to the final-year company revenue (₹315M). Dumb Waiter tickets are about a third of industrial ones |
| `complexity_score` | int 1–5 | Industrial accounts follow their region's complexity; Dumb Waiter is standardised (mostly 1–2) |
| `deal_cycle_days` | int | First meeting to order, CRM-style field. Industrial lines ~80–105 days; Dumb Waiter ~45 |
| `acquisition_year` | int | 2019–2024; all Dumb Waiter accounts are 2024 pilot customers |
| `current_rep_id` | string | FK → reps. Today's owner: a same-region rep, product-matched 70% of the time when possible. The as-is baseline for Module C |

## yearly_financials.csv (6 rows, 2019–2024)

A stress scenario for Module A: sales headcount grows 3.5× (16 → 56)
against 2.1× revenue. The real case runs the other way.

| Column | Description |
|---|---|
| `revenue_inr_m` | ₹150M → ₹315M |
| `cost_of_sales_inr_m` | 58% → 60% of revenue |
| `sales_payroll_inr_m` | Headcount × average rep cost. **2024 equals the sum of `reps.csv` exactly** |
| `sales_opex_inr_m` | Payroll + 12% for travel, phones, incentives |
| `other_opex_inr_m` | Admin, after-sales, design, quality: 13% of revenue |
| `depreciation_interest_inr_m` | 4% of revenue |
| `tax_inr_m` | 25% of profit before tax |
| `net_income_inr_m` | Net margin falls from ~12% (2019) to ~1% (2024) |
| `sales_headcount` | 16 → 56; 2024 equals `len(reps.csv)` |

## Traceability to the five questions

| Question | Tables used |
|---|---|
| A — is sales cost outrunning growth? | `yearly_financials` |
| B — which structure? | `accounts` (region, product, complexity, revenue) + `reps` (region, background, cost) |
| C — how many reps, who owns what? | Same, plus `accounts.current_rep_id` for the as-is baseline and the continuity charge |
| D — how to sell the new product? | `accounts` filtered to the Dumb Waiter vs. the rest (buyer segment, region, ticket, complexity, deal cycle) |
| Economics | Results of C and D, plus `yearly_financials` (final year) |
